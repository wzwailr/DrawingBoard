# DrawingBoard：现有产品替代性与重复开发复核

核验日期：2026-10-19。问题：是否已有足够接近的产品，是否仍值得继续开发？本文补充先前调研，不修改产品基线，也不改变另一开发分支的代码或任务状态。

## 结论

**有此类产品，通用功能重合很高。现有证据支持“先试用与局部适配”，不足以支持“市场上缺少这种产品，所以要完整自研”。**

需要修正先前讨论中的判断尺度：没有产品逐字满足我们的 23 项规则，不代表没有替代品。用户需要的是顺畅完成绘图、讨论和交付；不同手势同样可能完成任务，甚至更快。“按住规整”已有先例，也不是独立的原创卖点。

目前可验证的机会是：鼠标为主时，唤出、连续绘制、中文落字、移动与连线、导出这一整段流程是否明显更顺手。这仍是假设。没有对照操作数据，不能把它写成已证明的产品差异或商业机会。

## 本轮比上轮新增了什么

1. **Concepts Windows 的形状识别已明确核实。** [Windows 官方更新记录](https://concepts.app/en/windows/roadmap)在 2025.3 栏列出笔画末尾停顿识别，2026.1 又记录识别吸附改进；[官方操作手册](https://concepts.app/en/manual/precision-tools)说明末笔保持接触、调整激活时长。因此，上轮“Windows 是否具有该功能待确认”已被这次官方证据补足。鼠标端的实际手感、连接关系能力仍未实测。另一个帮助页把全平台正式发布标作 2025.4，与路线图月份有差异；这里不据此断言精确首次发布日。
2. 新增 **GazBoard**：具备大量直接重叠的白板功能；进一步读取了识别入口和连接线实现，不只看简介。
3. 新增 **Excalideck**：已经把 Excalidraw 做成本地桌面产品和文件库，不应把“给 Excalidraw 加桌面壳与本地管理”当作独有方向。
4. 新增 **FlowCraft** 和 **Hotkeys 的白板模块**作为边界对照：离线桌面白板、快捷键唤出 Excalidraw 都已有公开实现；不过功能和工程成熟度不能由 README 宣传直接认定。

## 优先比较的实际替代品

“官方说明”指产品方明确列出；“源码确认”指本轮读取对应实现；均不等于 Windows 安装实测。未确认不能写成不支持。

| 对象 | 已覆盖什么 | 对我们的替代程度与剩余核验 | 建议 |
| --- | --- | --- | --- |
| [Excalidraw](https://github.com/excalidraw/excalidraw) | 可编辑图形、文字、箭头绑定、手绘风格、无限画布、PNG/SVG/可编辑文件、PWA 离线。上轮真实网页已看到 Draw to shape 入口 | 结构图和静态页面布局高度重叠；我们的按住门槛、边框/内部仲裁不同。PWA 缓存离线不能等同于首次启动完全断网可用 | **通用编辑能力的主要对照；优先复用内核** |
| [Excalideck](https://github.com/GokulAnand14/excalideck) | 官方提供 Windows 安装包；本地文件夹、画布检索、后台保存、独立图片资源；Tauri + Excalidraw | 本地桌面形态也已存在。尚未实测全局唤出、中文 IME、断网冷启动和保存恢复。其 package.json 引用 Excalidraw `^0.18.0`，不能据此认定包含主分支最新识别 | **优先试用，评估直接用或局部改造** |
| [GazBoard](https://github.com/fahim9778/GazBoard) | Windows 离线免登录、无限画布、鼠标绘制、文字/图形/图片、本地自动保存、PNG/SVG/PDF/可编辑文件；源码有识别和绑定连接线 | 重叠很高。当前识别在松手时发生；不是我们的末尾停顿预览。普通笔迹/选择的规则也不同。快速唤出、完整命名区域语义未确认 | **值得与当前原型直接对照，纳入改造候选** |
| [Concepts Windows](https://concepts.app/en/windows/roadmap) | 官方确认末尾停顿识别，支持多笔和后续调整；有无限画布与矢量编辑体系 | 智能笔体验的直接先例。不要把识别出的可编辑线条等同于图编辑器的节点关系；双端绑定随动未确认 | **智能笔操作的主要对照；先实测鼠标** |
| [draw.io Desktop](https://www.drawio.com/docs/security/diagrams-offline/) | 正式离线桌面图编辑器，本地文件、结构图与关系编辑 | 可以完成许多同样的交付任务；操作偏图编辑，未确认我们的按住规整流程 | **若目标只是高效产出结构图，可能直接够用** |
| [Penlight](https://github.com/Ramonvdo/penlight) | Windows 托盘热键、持久白板、板库、自动保存、标注和讲解辅助 | 快开和随手演示高度重叠；主要是屏幕覆盖层。未确认可编辑节点绑定与停顿识别 | **快开和会议标注的对照，不直接视为完整替代** |

补充：

- [FlowCraft](https://github.com/alisheraxmedov/flowcraft-app)官方列出离线桌面、图形文字、分组、自动保存和 PNG/JSON；但也明确说明箭头尚不会随节点移动，PDF 不在当前导出列表。其 MCP 能力不影响我们关闭 AI 后使用普通白板，但也不构成继续开发本项目的理由。
- [Hotkeys](https://github.com/sprawf/hotkeys)官方说明用 Shift+F8 打开/关闭本地 Excalidraw，并自动保存。这至少证明“全局热键 + 离线 Excalidraw”的组合已有实现。它还带有许多无关工具，本轮没有审计或安装，不推荐仅为白板直接引入整套程序。

## GazBoard：为什么它足以改变我们的判断

源码固定提交：[`13beea0ccd86190e65d5124697dc948f6cbb87c6`](https://github.com/fahim9778/GazBoard/tree/13beea0ccd86190e65d5124697dc948f6cbb87c6)。

- [tools.js 的松手入口](https://github.com/fahim9778/GazBoard/blob/13beea0ccd86190e65d5124697dc948f6cbb87c6/src/js/core/tools.js#L987)在 draw 分支调用 finishStroke。开启 inkToShape 后，[识别与替换](https://github.com/fahim9778/GazBoard/blob/13beea0ccd86190e65d5124697dc948f6cbb87c6/src/js/core/tools.js#L1819)先提交原迹，再单独提交规整，撤销可回到原迹。这证明已经有可编辑转换与回退机制，但没有证明我们的停顿预览规则。
- [connectors.js](https://github.com/fahim9778/GazBoard/blob/13beea0ccd86190e65d5124697dc948f6cbb87c6/src/js/core/connectors.js#L1)包含目标 ID/组、两端和箭头头型；endBox 按当前对象计算边界。[finishShape](https://github.com/fahim9778/GazBoard/blob/13beea0ccd86190e65d5124697dc948f6cbb87c6/src/js/core/tools.js#L2083)在命中目标时创建 connector。这里核实的是代码机制，尚未运行验证随动、撤销或文件往返。
- 当前识别得到的线/箭头在 finishStroke 中作为 shape 创建，而手动线工具走 finishShape 的 connector 路径。因此不能推断“随手画出的线已经自动成为绑定连接线”；这是评估改造成本时要追踪的接缝。
- 项目根 [MIT 许可](https://github.com/fahim9778/GazBoard/blob/13beea0ccd86190e65d5124697dc948f6cbb87c6/LICENSE)已读取。它可以进入适配评估，但正式引入仍要核对实际使用的依赖和素材。

这比“另一个只能手写的笔记本”接近得多。不过仍不能断言把识别触发从松手改成按住就完成适配：预览、取消、边框命中、文字时序、原迹、绑定和历史都要联动验证。

## 重复到什么程度

| 我们想做的事 | 当前判断 | 开发含义 |
| --- | --- | --- |
| 无限画布、框、文字、图片、连线、选择、撤销、对齐、导出 | 成熟公共能力，多个替代品覆盖 | 没有理由从零自建整套内核 |
| Windows 桌面、本地保存、接着上次画、最近文件 | 已有专门桌面产品或可复用实现 | 优先直接使用、集成或改造 |
| 全局快捷键唤出与收起 | 已有产品和模块先例 | 不是独有壁垒，也不能仅凭“能注册热键”宣称快 |
| 随手画、末尾按住规整 | Concepts 等已有明确先例 | 可改进鼠标体验，不能当作原创机制 |
| 内部画、边框移动、双击落字、连线的统一规则 | 本轮未核实某一产品完整采用相同规则 | **可验证的定制方向**，并非已证明的优势 |
| 更少打断、更少误操作、更快完成会议草图 | 需要真实对照结果 | 这是继续开发最有说服力的依据 |

不提供“重复率 80%”之类数值：没有统一功能权重，也没有逐项运行验收，数字会产生虚假的精确性。

## 下一步如何决定，而不是继续堆功能

建议把正在做的 P0 保留为小范围原型，在进入 P1 前增加替代品对照。它是建议，不是已发送给另一个会话的指令。

优先对照 **Excalidraw/Excalideck、GazBoard、Concepts Windows**。按真实任务比较，不强制竞品模仿我们的手势：

1. 从日常工作切入画板，继续上次内容，并新建一个空白。
2. 画三个框、输入中文、连两条线，移动一个框后继续修改。
3. 画一个页面外框，在内部补导航、卡片和按钮，复制并调整一版方案。
4. 保留一笔随意涂鸦，将另一笔规整；遇到错误判断时恢复。
5. 展示结果、复制图片或导出，再关闭重开继续编辑。

记录完成时间、工具切换、误触和撤销纠正、输入法打断、重开后的关系/视角，以及主观顺手程度。给现有产品同等熟悉时间，使用其适合任务的最快操作；不要把“不是按住识别”自动记成任务失败。自研版也必须完成相同交付，而不是只演示理想笔画。

判定分三种：

- **直接使用**：现有工具已经让用户愿意在会议里实际使用，自研原型没有显著改善高频痛点。停止扩大自研范围并不浪费前期研究。
- **局部改造**：主要障碍集中在触发、窗口或少量交互接缝，并且许可、测试和升级维护成本可控。优先改造一个核心，避免多套编辑模型拼接。
- **继续自研产品**：经过相同任务比较，用户持续偏好自研流程，且可靠性没有下降；优势来自一段完整工作流，而非一个按钮位置。若目标是面向他人发布，还需另行验证目标用户需求，自己的偏好不能代替市场证据。

“我们已经开了开发分支”不是继续投入的理由；同样，“发现相似产品”也不自动要求放弃。此时合理投入是证明差异，尚不是补齐通用白板的所有功能。
